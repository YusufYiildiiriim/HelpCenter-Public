# help-center-ui

[English](README.md) · [Türkçe](README.tr.md)

Next.js 16 (App Router) frontend for HelpCenter. Part of the [HelpCenter](../README.md) monorepo —
see the root README for the full picture (architecture, tech stack, quick start for the whole
stack) and [SECURITY.md](../SECURITY.md) for the security posture.

## Local development

```bash
# First, from the repository root: cp .env.example .env
# Then, from help-center-ui:
../scripts/with-env.sh npm ci
../scripts/with-env.sh npm run dev
# → http://localhost:3000
```

`../scripts/with-env.sh` loads the repository-root `.env` for that command only. Next.js does not
automatically read a parent-directory `.env`, so keep the shared local configuration in the root
file instead of recreating `help-center-ui/.env.local`.

`src/proxy.ts` uses the `refresh_token` HttpOnly cookie only as a coarse route gate. The access
token stays in module memory and protected layouts verify it through the API; no frontend JWT
signing secret is needed.

For production, set `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_APP_URL`, and
`AppSettings__FrontendUrl` to the public HTTPS origin; none may point at `localhost`. Production
Compose reads these values directly from the root `.env` and Caddy routes API and SignalR traffic.

CKEditor runs under the repository's GPL-3.0-only license. If the editor cannot initialize, the
route's standard error page is shown instead of a blank editor.

`/dashboard/sso` is disabled by default. Set `NEXT_PUBLIC_DEMO_SSO_ENABLED=true` only in a
controlled environment; it is a memory-only demo bridge, not OIDC or SAML SSO.

## Frontend conventions

The public portal intentionally uses a dark visual identity; the admin/dashboard intentionally
uses a light operational shell. There is no end-user theme toggle in the current product slice.
Semantic surface/content/border/action tokens are available in `globals.css`; extend them instead
of introducing another independent colour vocabulary.

- Keep App Router entry points (`page.tsx`, `layout.tsx`, `loading.tsx`, `error.tsx`, and
  `not-found.tsx`) in `src/app` and limited to routing/layout responsibilities.
- Co-locate route-private UI in the route segment's `components/` directory. Put route-agnostic
  shared UI in `src/components/`, client providers in `src/context/`, and API transport modules in
  `src/services/`.
- Import code under `src` via `@/`; use relative imports only inside one small route or feature
  folder.
- Use local React state for ephemeral UI state. New client-side server state follows TanStack Query
  as it is introduced feature by feature.
- Build new dialogs from `src/components/common/AppDialog.tsx`, which composes the shared Radix
  primitive in `src/components/ui/dialog.tsx`; do not hand-roll modal semantics with generic elements.
- At touched API boundaries, prefer types generated by `npm run api:types`. New or substantially
  revised complex forms should use React Hook Form with Zod; migrations are incremental.

The rationale and adoption boundaries are recorded in
[ADR-008](../docs/adr/008-frontend-foundation.md).

## Browser and component assurance

Install the Chromium binary once before running the browser suite:

```bash
npx playwright install --with-deps chromium
npm run e2e
```

The public-home E2E suite starts Next on port `3001` and fulfills every public API request
with Playwright fixtures. It therefore does not require Docker, a running backend, credentials,
or seeded data. Keep authenticated flows in a separate suite with explicit test credentials.

Storybook catalogs the route-agnostic primitives under `src/components/**`: Button, FormField,
AppDialog and API state variants. The a11y addon provides interactive feedback; the Playwright
axe smoke test is the blocking automated check. `color-contrast` is the single temporary
baseline exception: it covers pre-existing public-portal palette debt and should be removed by
the semantic-theme migration rather than broadened with further rule exclusions.
